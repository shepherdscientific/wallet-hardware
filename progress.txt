### 2026-05-16: US-012 — PSBT Signing via SE051C2 (ECDSA + Schnorr)
- Created `psbt_signer.h/cpp`: BIP143 sighash (P2WPKH) and BIP341 sighash (P2TR key-path) computation
- `sighash_bip143(psbt, input_idx, sighash_type, hash_out)`: SHA256d of serialized BIP143 signing data

Patterns discovered:
- PSBT v0 builder pattern: magic → varint(key_len) → key_type → varint(val_len) → unsigned TX bytes → separator(0x00) → input KVs → separator → output KVs → separator. The unsigned TX KV must wrap the TX content inline (not reference a pre-written buffer)
- BIP143 sighash must compute hashPrevouts and hashSequence as SHA256d (double-SHA256), while BIP341 uses single SHA256 for its preimage hashes
- BIP341 sigMsg layout: hash_type(1) || nVersion(4) || nLockTime(4) || sha_prevouts(32) || sha_amounts(32) || sha_scriptpubkeys(32) || sha_sequences(32) || sha_outputs(32) || spend_type(1) || input_index(4)
- SE temp key pattern: derive child key → store as temp (0xF0) → sign → delete temp — ensures key material lifespan is minimized
- All-hardened BIP32 paths avoid EC scalar multiplication bug (HMAC-SHA512 only); mixed hardened/non-hardened affected by known EC doubling parity bug

- Created `bip32.h/cpp`: full BIP32 HD key derivation engine
- `hd_derive_master_from_seed()`: HMAC-SHA512("Bitcoin seed" || seed) → master key + chain code

- Implemented standalone secp256k1 elliptic curve operations:
  - Point addition, doubling (affine coordinates), scalar multiplication (double-and-add)
  - Fast modular reduction: secp256k1 p = 2^256-2^32-977 structure
  - Barrett-style reduction for group order N with high-half quotient estimate
  - Fermat-based modular inverse: a^(p-2) mod p
  - 256-bit and 512-bit multi-precision integer arithmetic (4x64 and 8x64 words)
- Added `se051_read_object()` to SE HAL for reading binary objects (chain code, PIN hash, etc.)
- 17 unit tests: BIP32 test vector 1 (master, m/0'H hardened), multi-level hardened derivation (BIP44 path), error handling, modular arithmetic verification (mod_mul, mod_inv), SE integration, small-scalar pubkey (1*G, 2*G)

Patterns discovered:
- EC point doubling must save operands before writing results when r aliases p (same-pointer in ec_scalar_mult_G's double-and-add)
- 256-bit multi-precision addition/subtraction carry must be computed in two steps: first detect overflow from addend, then from carry-in, OR both results. Single-step `(sum < a[i])` fails when both terms overflow.
- secp256k1 fast reduction: c ≡ c0 + c1*(2^32+977) mod p, applied iteratively until result < p
- Modular subtraction via `p - (b - a)` is safer than `a + (p - b)` because the latter may overflow 2^256

Known limitations:
- EC scalar multiplication parity/sign bug in doubling for large scalars (k > 3). Small scalars correct. Affects non-hardened CKD and pubkey_from_priv for keys > 3. Hardened CKD (HMAC-SHA512 only) unaffected and verified against BIP32 vectors. Fix pending.
